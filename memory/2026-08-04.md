**✅ The math is fully programmatic.**
- Single path: `buildTabla` → `aggregateValues(values, op)` (`tools.ts:451-467`).
- `aggregateValues` is plain JS — `reduce`, `Math.min/max`, divide-by-length.
- `readNumericCell` (`tools.ts:473-485`) rejects null, non-numeric strings, NaN, Infinity.
- TOTAL row appended as `{_tipo:"total", [col]: valor.toFixed(3) + unidad}` with unit inferred from the Qto_ key.
- UI separates total rows before filter/sort (`QuantificationPanel.tsx:176-180`) — aggregate never gets hidden.
- `totales: {operacion, columna, valor, unidad}` is returned in the function response — the exact number, not the prose.
- LLM chooses which column + which op. LLM does NOT compute, edit, or override the value.

**⚠ Two residual risks in prose (not in the math):**
1. LLM prose drift — prompt says "reporta el valor exacto con su unidad" (`prompts.ts:34`) but nothing enforces it. Gemini could write a different number than the table.
2. LLM prose without the tool call — no enforcement that a quantity question must call the tool.

**Suggested hardening (not shipped):** inject the formatted total into the final-turn prompt when a tool response carries `totales` — same pattern as evidence summaries at `loop.ts:118-129`. Closed in 30 min, no new UI. Boss said he'd think about it; not actioned yet.
